1 Scope & Business Goals Oct 14 · 9–10am
Confirmed
  • Tier 1 (full self-service): password reset, 2FA, ID verification, deposit status, location check
  • Tier 2 (guided + possible handoff): withdrawal status, failed transactions, bet disputes, promo eligibility, "how to contact support"
  • Tier 3 (Necessary Transfer — not deflection targets): account locked, fraud, RG escalation
  • Primary metric = containment rate, not raw deflection count. Tier 3 contacts routed to humans are not agent failures.
  • Article rewrites for top Tier 1 intents are a prerequisite for agent quality — not a parallel workstream
Open in session
  • Operating hours — after-hours window confirmed? (3–7am?)
  • Peak volume windows — game days, Super Bowl, major events?
  • Containment rate target (baseline needed first)
  • CSAT and handle time baseline from current chatbot?
  • Phase 1 priority ranking within Tier 1
2 Current-State Support Model Oct 14 · 10–11am
Confirmed
  • 48.5% chat rate confirmed from Help Portal article analysis — primary pain point driving this project
  • Top contact reasons by volume: password/login, ID verification, 2FA, withdrawal status, location check
  • Location Troubleshooting article is a high-performing pattern (step-based + deeplink) — replicate across other Tier 1 intents
  • Necessary Transfer flows (Account Locked, Contact Us) should be expectation-setting only — no resolution attempt
Open in session
  • After-hours staffing model and current vendor coverage
  • Existing chatbot platform — can it pass conversation context to a human on handoff?
  • Which flows to keep vs. redesign from the current bot?
  • Current handle time per intent type?
3 Channels & Customer Experience Oct 14 · 11:15am–12:15pm
Confirmed
  • Primary channel: EC Help Portal — agent embedded on homepage and article pages
  • 82% of Help Portal visitors arrive from a FanDuel app (SBK/Casino/DFS/Racing)
  • 91% mobile or tablet — mobile-first design required, not adapted from desktop
  • Context at launch defined: from app = personalised greeting + product pre-load; authenticated = name only; unauthenticated = generic
  • Tone: direct, plain English, warm but efficient. Brevity over polish.
  • English (US) — localization/language variants TBC
  • Fallback when agent can't help: acknowledge, do not loop, offer escalation before ending session
Open in session
  • Same-agent or subagent? If the FanDuel app opens a support agent, is it the same agent as the Help Portal or a separate deployment? This is the single biggest architectural decision.
  • Web widget — same agent definition or lighter variant?
  • Agent name — brand name or "FanDuel Help Agent"?
  • Languages beyond English US required?
4 Escalation & Human Handoff Oct 14 · 1–2pm
Confirmed
  • 5 escalation triggers: account locked/suspended · fraud/unauthorised access · active RG flag · 3 failed resolution attempts on same intent · user requests human
  • Escalation experience: acknowledge without blame → set wait expectations (real figures only, no invented SLAs) → pass full context to human
  • Context must pass to human — user should never repeat themselves
  • Tier 3 (Necessary Transfer): agent sets document/info expectations before routing ("Have your ID ready")
Open in session
  • Who is available after hours — and for which case types?
  • Case creation and routing — Omni-Channel or callback/follow-up flow?
  • SLA expectations by case type
  • Does the current chatbot platform support context pass on handoff? (If not, this is a technical prerequisite.)
5 Data & Knowledge Oct 14 · 2–3pm
Confirmed
  • EC Knowledge articles are the single source of truth — no parallel knowledge base assumed
  • Monthly SME review cycle confirmed (July/May/June/August 2026 waves)
  • Article format requirements for agent consumption: numbered steps, decision branches, inline deeplinks, H2/H3 headings — narrative paragraphs produce imprecise answers
  • Narrative rewrites for top Tier 1 articles are a prerequisite — must happen before agent goes live, not in parallel
  • Customer/account data needed: user_id, account_status, product, last_page (from app session)
Open in session
  • Who owns each article category — and who approves rewrites?
  • How fresh are promo/bonus T&C articles? These change frequently.
  • Is Amplitude integrated? Intent frequency analysis and "trending topics" surface depend on it.
  • Where does account/wallet data live — Salesforce, billing system, or both?
6 Actions & Integrations Oct 14 · 3:15–4:15pm
Confirmed
  • Context parameters at launch: product · user_id · account_status · last_page
  • RG flag lookup required at session start — gates the entire session if active
  • Deeplinks for procedural Tier 1 intents (reset flow, verification flow, etc.) are required actions, not nice-to-haves
  • Read-only actions for MVP — transactional actions are Phase 2+
Open in session
  • Who owns the support entry point in each app (SBK / Casino / DFS / Racing)?
  • Which APIs are available and who owns them?
  • Authentication approach for the agent — session token passthrough or re-auth?
  • Integration team availability and constraints?
7 Compliance, Risk & Guardrails No date set — schedule ASAP
Recommend scheduling before or alongside Topic 6. For a sports betting operator, compliance gates the actions session — you can't finalize what the agent does until guardrails are defined.
Confirmed
  • RG gate is a hard rule — non-configurable, no commercial override
  • When RG flag is active: surface only RG resources · no bonuses/promos · do not attempt to retain · route and close
  • Necessary Transfer topics: account locked, fraud/unauthorized access, regulatory complaints
  • Agent must never offer or acknowledge bonuses/promos during a Tier 3 or RG-flagged session
Open in session
  • State-specific RG routing: which states require specific helpline numbers (e.g. NJ 1-800-GAMBLER)? Which states have different self-exclusion or cooling-off rules the agent must respect?
  • Full list of topics agent must never discuss or always escalate
  • Legal / compliance / security review steps and approval chain
  • Audit, logging, and data retention requirements per state
  • PII handling rules for conversation transcripts
